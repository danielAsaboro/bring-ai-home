## First, which kind of model?

"AI model" covers very different tools.
A language model reads and writes text.
A speech model turns audio into text, an embedding model turns text into numbers you can compare, and a decision model like the one we'll meet in lesson 06 answers questions you define.

So the first question is always the same: what kind of data do you have?
Most of the clever models only read text.
Anything else, an image, a scan, a recording, has to become text first.

| You have | Turn it into text with | QVAC docs |
|---|---|---|
| A screenshot, photo or scanned page | OCR, or a vision-language model | [OCR](https://docs.qvac.tether.io/sdk/ai-capabilities/ocr/), [Multimodal](https://docs.qvac.tether.io/sdk/ai-capabilities/multimodal/) |
| A voice note or meeting recording | Speech-to-text (transcription) | [Transcription](https://docs.qvac.tether.io/sdk/ai-capabilities/transcription/) |
| A PDF made by a computer | Read its text layer directly; use OCR only for scans | [OCR](https://docs.qvac.tether.io/sdk/ai-capabilities/ocr/) |
| Text already | Nothing: hand it to a text model | [Text generation](https://docs.qvac.tether.io/sdk/ai-capabilities/text-generation/) |

## Why OCR, not a vision model?

For images there are two options, and they answer different questions.
A vision-language model looks at the picture and *describes* it: "a chat between Maya Chen and a colleague about a contract".
OCR *transcribes* it: every line of text, exactly, with a box around where it sits.

Redact needs the second.
To cover a phone number we need its characters, to decide it's private, and its position, to draw a black box over exactly those pixels.
A vision model can tell you there's a phone number; it can't reliably tell you which 300 pixels to paint.

OCR is also small and fast.
QVAC's English OCR is two files, about 98 MB, and reads a page in roughly 20 seconds on a laptop.
The same reasoning goes for audio: if you needed to know *when* each word was said, you'd want a transcription model that returns timestamps, not one that only summarises.

More on this choice, for any app: [Choosing the right model for your data](/docs/redact/concepts/choosing-a-model).

## How QVAC's OCR works

It runs in two stages.
A **detector** finds the regions of the image that look like text.
A **recognizer** reads the characters inside each region.

You get back a list of **blocks**.
Each block has the `text`, a `bbox` (the box's pixel corners in the image) and a `confidence` between 0 and 1.
Confidence means "how sure am I about these characters", not "is this private"; that's a separate question, and a separate model, later.

We'll run it from a small script, outside the app.
If anything goes wrong with installing or downloading, it goes wrong here, on its own, where it's easy to see.

## 2. Read the script before running it

Open `qvac-service/ocr-smoke.mjs`.
It does five things, in this order.

**It picks the image and fingerprints it.**

```js
const sourcePath = path.resolve(process.argv[2] ?? defaultSource);
const sourceBytes = await readFile(sourcePath);
const sourceDigest = createHash("sha256").update(sourceBytes).digest("hex");
```

With no argument it reads `public/test-files/redact/chat-private.png`.
The SHA-256 digest ties the output to this exact file, so you can tell later which image a result came from.

**It tells QVAC where to keep models, before loading QVAC.**

```js
await mkdir(cacheDirectory, { recursive: true });
await writeFile(
  configPath,
  `${JSON.stringify({ cacheDirectory }, null, 2)}\n`,
  "utf8",
);
process.env.QVAC_CONFIG_PATH = configPath;

sdk = await import("@qvac/sdk");
```

QVAC reads its configuration once, when it starts.
So the script writes `.qvac/config.json` with a `cacheDirectory` inside the app, points `QVAC_CONFIG_PATH` at it, and only then imports the SDK.
That keeps Redact's models in `redact/.qvac/models` instead of a shared folder in your home directory.
QVAC's background worker still keeps a little of its own state, a download registry and temporary files, in `~/.qvac` ([Where QVAC writes files](/docs/qvac/where-qvac-writes-files)).

**It loads the OCR model.**

```js
modelId = await sdk.loadModel({
  modelSrc: sdk.OCR_LATIN,
  modelConfig: {
    langList: ["en"],
    magRatio: 1.5,
    defaultRotationAngles: [90, 180, 270],
    contrastRetry: false,
    lowConfidenceThreshold: 0.5,
    recognizerBatchSize: 1,
  },
});
```

`OCR_LATIN` is a catalog name for the detector and recognizer pair; the first call downloads them.
`langList: ["en"]` reads English, `magRatio: 1.5` enlarges the image a little so small text is easier to detect, and `defaultRotationAngles` lets the recognizer try sideways text.
`loadModel` returns a `modelId`, which every later call uses.

**It reads the image.**

```js
const run = sdk.ocr({
  modelId,
  image: sourcePath,
  options: { paragraph: false },
});
const [blocks, stats] = await Promise.all([run.blocks, run.stats]);
```

`paragraph: false` keeps each line as its own block instead of merging nearby lines.
We want lines: a phone number should be its own box, not part of a paragraph.

**It cleans up, even when something fails.**

```js
} finally {
  if (sdk && modelId) {
    await sdk.unloadModel({ modelId, clearStorage: false }).catch(() => undefined);
  }
  if (sdk) await sdk.close().catch(() => undefined);
}
```

`unloadModel` frees the memory but keeps the downloaded files (`clearStorage: false`).
`close` stops QVAC's background worker so the script can exit.

## 3. Run it

```bash
npm run qvac:ocr-smoke
```

If you did lesson 00, nothing downloads here: the models are already in `redact/.qvac/models`.
Otherwise the first run downloads the two model files, about 98 MB, which takes a minute or two depending on your connection, then reads the image.

On a first run, QVAC's download logs come first, many lines starting `[QVACRegistryClient] [INFO] Downloading blob…`.
They go to the same output and can't be redirected, so the JSON comes at the end.
It starts like this:

```json
{
  "sourceName": "chat-private.png",
  "sourceDigest": "…",
  "cacheDirectory": "…/redact/.qvac/models",
  "blocks": [
    {
      "text": "Maya Chen",
      "bbox": [ … ],
      "confidence": …
    },
```

Your digest, paths and exact numbers will differ.

If it fails, the last line starts with `QVAC OCR smoke failed:`.
The usual causes are an interrupted `npm ci` (run it again) or no internet on the first run (the model has to download once).
If the message mentions `ENOENT` and `stat "…/.qvac"`, your `~/.qvac` is a broken link or isn't writable: replace it with a real folder (`mkdir ~/.qvac` once the old link is gone).

## 4. Read the blocks

Scroll through `blocks`.
There are 12, one per line or phrase in the image:

```text
Maya Chen
maya.chen@example com
Please send the contract to 18 Willow Road.
My
phone is +1 415 555 0184.
Got it.
will use account 8841 0932
and reference APOLLO-4471
Thanks
keep the amount confidential.
Controlled test document
no real personal information
```

Notice the second line: OCR lost the dot in `example.com`, and its `confidence` is lower than the clean lines around it.
Small mistakes like this are normal, and the rest of the course is built to live with them.

Notice too that the private details aren't always whole lines.
"phone is +1 415 555 0184." mixes ordinary words with a number; we'll come back to that in lesson 06.

Each `bbox` is four numbers: the top-left and bottom-right corners, in pixels of this image.
They're what will let us draw boxes in exactly the right place, in lesson 05.

## 5. Run it again

```bash
npm run qvac:ocr-smoke
```

This time nothing downloads.
The output ends with `stats`, something like:

```json
"stats": {
  "detectionTime": 18.1,
  "recognitionTime": 1.1,
  "totalTime": 19.2
}
```

The times are in seconds.
Finding where the text is takes almost all of it; reading the characters is fast.

Look in `redact/.qvac/models`.
There are two files: `…craft_mlt_25k.gguf` is the detector and `…latin_g2.gguf` the recognizer.
