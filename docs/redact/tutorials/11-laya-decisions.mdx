In this lesson we will stop asking a language model to write JSON. Instead, we ask [Laya](https://docs.qvac.tether.io/sdk/ai-capabilities/decisions/), QVAC's decision model, one yes/no question per field about each line of OCR text and read back a probability. Then we use the same model to check the flattened copy for anything still readable, and we measure Laya against Qwen on the lesson 9 evaluation.

**Checkpoint:** [`446b69c`](https://github.com/danielAsaboro/bring-ai-home/commit/446b69caf8003249f5c024f66fb657a50c054375)

## 1. Apply the patch

Stop the app and the service. Download [`11-laya-decisions.patch`](/docs/downloads/redact/11-laya-decisions.patch) into `~/Downloads`, then from the parent `redact-course` folder:

```bash
git apply --check ~/Downloads/11-laya-decisions.patch
git apply ~/Downloads/11-laya-decisions.patch
cd redact
```

No packages change, so there's nothing to install. If `--check` fails, your lesson 10 files differ from the checkpoint; compare them before going on.

The patch adds `qvac-service/decision-reasoner.ts`, which asks one question per field, such as "This text contains a person's name.", and `qvac-service/reasoner-choice.ts`, which picks Laya unless `REDACT_REASONER=qwen` is set.

## 2. Ask Laya about one page

Start the service:

```bash
npm run qvac:service
```

In a second terminal, start the app:

```bash
npm run dev -- --port 3101
```

Open [http://localhost:3101](http://localhost:3101). Upload `public/test-files/redact/chat-private.png`, choose **Private**, and type this direction:

```text
Redact direct identifiers, account numbers, and reference codes.
```

Select **Prepare for review**. The first time, QVAC downloads Laya (`laya-Q8_0.gguf`, 450 MB), so this run takes a few minutes. After that, the whole page takes about 30 seconds, nearly all of it OCR.

![Seven suggestions from Laya on the review screen](/docs/redact/images/laya-review.png)

You should see **7 suggested redactions**: the name, email, address, phone, account and reference, plus `keep the amount confidential.` labelled **OTHER**. That last one comes from your direction: Laya is asked "This text is something the user asked to hide: …" alongside the six field questions, and it said yes.

## 3. Check the copy

Reject the **EMAIL** suggestion and accept the rest. Select **Done**.

The finished screen shows **Checking the copy locally for anything still readable…** for about 25 seconds. Then:

![The copy check listing the email that is still readable](/docs/redact/images/laya-copy-check.png)

Redact sent the flattened copy back through OCR and Laya. The covered fields came back as black boxes, so OCR found no text there; the email you rejected is still readable, so it's listed. **Save copy** stays enabled: the check reminds you, it doesn't decide for you.

Select **Return to review**, accept the email, and select **Done** again. This time the check reads **Local check: nothing private is readable on the copy.**

## 4. Measure Laya against Qwen

Stop the service with `Ctrl+C`; the evaluation runs its own copy of the models. Run the lesson 9 evaluation with each model:

```bash
REDACT_REASONER=laya npm run --silent qvac:evaluate > laya.json
REDACT_REASONER=qwen npm run --silent qvac:evaluate > qwen.json
```

Each takes about two minutes. The Qwen run downloads Qwen3 0.6B first if you haven't cached it. Both should print `"passed": true` near the top of their file. Compare the per-case `f1` values and the `timings`:

| Case | Laya F1 | Qwen F1 |
|---|---|---|
| `chat-clear` | 0.92 | 0.91 |
| `chat-rotated` | 0.92 | 0.91 |
| `chat-low-contrast` | 0.92 | 1.00 |
| `chat-partially-obscured` | 0.83 | 0.91 |
| Time to decide, per page | about 0.8 s | about 6 s |

Notice how the two models get things wrong. Laya finds all six fields on three pages and adds one suggestion that isn't labelled (the "amount" line). Qwen never adds one but misses a field on three pages. Run Laya twice: both runs give the same answers, with no sampling settings to pin.

## What we built

Redact now asks a 421M-parameter decision model plain yes/no questions instead of asking a generator to write JSON. Each decision is about seven times faster, comes with a real probability, and repeats exactly. And the same model now checks the copy before it leaves your machine, which catches the riskiest kind of mistake: a field nobody covered.
