## Two ways to describe a box

OCR and the editor describe the same rectangle in different languages.

| | OCR's `bbox` | The editor's mark |
|---|---|---|
| Shape | `[x1, y1, x2, y2]` | `{ x, y, width, height }` |
| Meaning | Top-left corner, bottom-right corner | Top-left corner, plus size |
| Units | Pixels of the image OCR read | Percent of the page |

The editor uses percentages because the page is drawn at different sizes: big on a monitor, small on a phone, scaled in the safe-share preview.
A mark at `x: 17.5%` stays on the same word at any size.
OCR uses pixels because that's all it knows: the image it was given.

So every box needs converting once, from pixels to percentages, using the size of the exact image OCR read.
That's why lesson 04's service refused images whose size didn't match the request.

## Why be so strict about bad boxes?

A wrong outline is worse than no outline.
If an outline sits a line too low, a reviewer who trusts it covers the wrong words and shares the real ones.
So the conversion fixes what it safely can, like corners given in the wrong order or a box that pokes past the page edge, and throws away what it can't.

More on OCR's coordinates, including what rotation does to them: [OCR boxes and rotation](/docs/qvac/ocr-geometry).

## 2. Convert one box by hand

The chat image is 1200 pixels wide and 1600 pixels high.
In one run, OCR returned this box for `Maya Chen`:

```text
[211, 114, 397, 158]     x1, y1, x2, y2 in pixels
```

The editor wants the top-left corner and the size, each as a percentage of the page:

```text
x      = 211 / 1200 × 100          = 17.583333
y      = 114 / 1600 × 100          = 7.125
width  = (397 − 211) / 1200 × 100  = 15.5
height = (158 − 114) / 1600 × 100  = 2.75
```

Notice the subtraction.
Dividing all four numbers by the page size would give you the bottom-right corner, not the size, and every mark would be far too big.

## 3. Read the conversion

Open `src/features/redact/ocr-geometry.ts`:

```ts
export function normalizeOcrBbox(
  raw: readonly [number, number, number, number],
  sourceWidth: number,
  sourceHeight: number,
): BoundingBox | null {
  if (!Number.isFinite(sourceWidth) || !Number.isFinite(sourceHeight) || sourceWidth <= 0 || sourceHeight <= 0) {
    throw new Error("Source dimensions must be positive");
  }
  if (!raw.every(Number.isFinite)) return null;

  const x1 = clamp(Math.min(raw[0], raw[2]), sourceWidth);
  const y1 = clamp(Math.min(raw[1], raw[3]), sourceHeight);
  const x2 = clamp(Math.max(raw[0], raw[2]), sourceWidth);
  const y2 = clamp(Math.max(raw[1], raw[3]), sourceHeight);
  if (x2 <= x1 || y2 <= y1) return null;

  return {
    x: percentage(x1, sourceWidth),
    y: percentage(y1, sourceHeight),
    width: percentage(x2 - x1, sourceWidth),
    height: percentage(y2 - y1, sourceHeight),
  };
}
```

Read it top to bottom:

1. A page with no size is a bug, so it throws.
2. A box with `NaN` or `Infinity` in it is skipped (`null`).
3. `Math.min` and `Math.max` put the corners in order, whichever way OCR gave them.
4. `clamp` pulls each edge back onto the page.
5. If nothing is left, because the box had no width or lay entirely off the page, it's skipped.
6. Otherwise it's converted, using `x2 - x1` for the width as you did by hand.

`percentage` rounds to six decimal places, which is why you get `17.583333` instead of a long fraction.

## 4. Read where it's used

In `RedactApp.tsx`, each OCR block is converted as it arrives:

```ts
...result.ocrBlocks.flatMap((block, index) => {
  const bbox = normalizeOcrBbox(block.bbox, page.width, page.height);
  return bbox
    ? [{
        id: `ocr-${page.id}-${index + 1}`,
        documentId: session.source.id,
        pageId: page.id,
        pageNumber: page.pageNumber,
        text: block.text,
        rawBbox: block.bbox,
        bbox,
        confidence: block.confidence,
      }]
    : [];
}),
```

`flatMap` with an empty array is how a skipped box disappears.
The block keeps `rawBbox` too, so you can always see what OCR originally said.

`DocumentSurface.tsx` then draws one dashed outline per block, positioned with the percentages:

```tsx
{mode === "original" && evidence.map((block) => <span aria-label={`OCR evidence ${block.text}`} className="ocr-surface-evidence" key={block.id} style={{ left: `${block.bbox.x}%`, top: `${block.bbox.y}%`, width: `${block.bbox.width}%`, height: `${block.bbox.height}%` }} />)}
```

Only on **Original**, never on the safe-share preview: outlines show evidence, they don't cover anything.

## If something goes wrong

- **Outlines are offset from the text:** the page the browser shows isn't the image OCR read.
  That's what the size check in lesson 04 prevents; make sure you're on this lesson's code with `git log --oneline -1`.
- **No outlines and "Drag to draw · drag marks to move" in the header:** no OCR blocks came back, usually because the service isn't running.
  The OCR panel on the right will be missing too.
