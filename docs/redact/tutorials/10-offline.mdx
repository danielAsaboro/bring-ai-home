<Note>
This lesson needs **macOS**: it uses the built-in `sandbox-exec` tool to deny network access.
On Linux or Windows, see [How to run Redact offline](/docs/redact/how-to/run-offline) instead.
</Note>

In this lesson we will prove that Redact's analysis needs no network once its models are cached: first with one analysis inside a sandbox that blocks remote connections, then with the full app driven by a browser test.

**Checkpoint:** [`1d432a2`](https://github.com/danielAsaboro/bring-ai-home/commit/1d432a28deef8ce15e32f1f1b45a2d86d833d591), starting from `ad636f7`

## 1. Apply the lesson's changes

Download [`10-offline-proof.patch`](/docs/downloads/redact/10-offline-proof.patch) into your Downloads folder.
Stop the app and the service, then from the parent `redact-course` folder:

```bash
git apply --check ~/Downloads/10-offline-proof.patch
git apply ~/Downloads/10-offline-proof.patch
cd redact
npm ci
```

If `--check` reports an error, your folder doesn't match lesson 09's checkpoint; fix that before going on.

## 2. Make sure both models are cached

```bash
ls .qvac/models
```

You should see three files: one containing `craft`, one containing `latin`, and `…_Qwen3-0.6B-Q4_0.gguf`.
If any is missing, run one analysis in the app with the network on first.
The offline commands refuse to start with `QVAC cache is incomplete` otherwise.

## 3. Run one analysis with the network denied

With the service stopped:

```bash
npm run --silent qvac:offline > offline-receipt.json
```

It takes about half a minute.
Open `offline-receipt.json`.
You should see:

```json
"mode": "macos-process-network-denied",
"osNetworkDenied": true,
"ocrBlocks": 12,
"suggestions": 6,
"labels": ["name", "email", "address", "phone", "account", "reference"],
```

and under `run`, `"status": "ready"` with `ocrMs` and `reasoningMs` timings.
Those six labels are the same suggestions you saw in the app, produced while the process couldn't reach anything beyond `localhost`.

## 4. Run the app with a sandboxed service

Build the app once:

```bash
npm run build
```

Then in one terminal start the service inside the same sandbox:

```bash
npm run qvac:service:offline
```

and in a second terminal start the built app:

```bash
npm run start -- --port 3101
```

## 5. Run the browser receipt

In a third terminal, inside `redact`, install Playwright's browser once:

```bash
npx playwright install chromium
```

Then run the live test:

```bash
REDACT_LIVE_QVAC=1 npx playwright test e2e/offline-qvac-workflow.spec.ts --project=desktop
```

After a minute or so it prints `1 passed`.
In that time the test uploaded the chat, waited for local suggestions, accepted the name, rejected the email, accepted the rest, added a manual mark, saved the copy, checked that a pixel inside the name is black, checked that the source file's SHA-256 didn't change, and checked that the browser made no request to any host other than `localhost` or `127.0.0.1`.

Without `REDACT_LIVE_QVAC=1` the test is skipped, not passed.

## 6. Run the checks

Stop the app and the service, then:

```bash
npm test -- qvac-service/offline-proof.test.ts
npm run lint
npm run typecheck
npm test
```

`npm test` should end with `Tests  88 passed (88)`.
Keep `offline-receipt.json` outside the app or delete it, then record the final checkpoint from the parent folder:

```bash
cd ..
git add redact
git -c user.name="Course learner" -c user.email="learner@example.invalid" commit -m "Lesson 10: run Redact with the network off"
```

## What we built

The finished Redact: local OCR and a local model propose, a person decides, and a new flattened copy is saved, with a receipt that the analysis ran with remote networking denied.
The sandbox proves what the QVAC process could reach; it doesn't prove the copy caught every sensitive field.
