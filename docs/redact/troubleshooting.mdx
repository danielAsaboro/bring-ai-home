---
title: "Troubleshoot a course checkpoint"
description: "Find the failing boundary before changing the model, service, or product."
---

Start with the exact command, chapter, source checkpoint, and error. Keep the error message, but remove private document text or image bytes before sharing logs.

## The chapter patch does not apply

Confirm that you are in the parent `redact-course` directory and completed the preceding chapter. Run `git status --short` and `git diff` to inspect your edits.

The patches use paths such as `redact/package.json`. They are not meant to be applied from inside the application's `redact` directory. A completed-source download already contains later changes and is not the starter.

Do not use forced patch application or reset an unrelated working directory. Compare against a separately unpacked reference instead.

## npm fails with EPERM

If the error points to the npm cache, use a writable scoped cache:

```bash
npm ci --cache /private/tmp/redact-course-npm-cache
```

If it names another location, investigate that location. A cache permission failure is not an inference failure.

## QVAC's worker cannot find a plugin

An interrupted dependency installation can leave the SDK directory present while native plugin packages are missing. Stop the service and complete `npm ci` from the chapter's lockfile.

Check the Node version and native-platform support before changing model configuration. Do not replace a missing runtime with canned OCR and call it a successful local run.

## The first model run needs the internet

Dependency installation, model acquisition, model loading, and inference are different stages. Complete acquisition online before attempting Chapter 10.

An existing `.qvac` directory is not proof that every required asset is complete. The offline cache guard and real cached inference must succeed.

## The service does not start

Read stderr before testing the browser. A runtime error before `127.0.0.1:4317` opens belongs to the entrypoint or its dependencies.

The historical TypeScript runner needed an explicit async `main()` instead of top-level await. Use the checkpoint implementation rather than mixing early service code with later configuration files.

## Health says ready, but a model is not loaded

This is expected before the first lazy load. The process can accept requests without an active model in memory. After successful inference, inspect the model state again.

A `busy` service is already holding its inference slot. Wait for it to settle before retrying.

## Raster dimensions do not match

Read the dimensions from the decoded image bytes. Do not hard-code the dimensions from a thumbnail or another test image.

The controlled chat page used in the historical scripts is 1200×1600. That number is not a general document rule. The app sends measurements for each prepared page and the service verifies them.

## OCR works, but outlines cover the wrong text

Check whether the raw tuple represents pixel edges and whether you converted it to percentage origin and size. Normalize once against the measured source dimensions.

Confirm that the displayed raster is the analyzed raster, and that the page ID matches. On a rotation-recovery path, transform recovered coordinates back to the original page before rendering.

Run the geometry tests before changing CSS to compensate for a data error.

## A JSON-shaped response is still wrong

Inspect parsing, runtime schema validation, stop reason, index bounds, duplicates, and semantic validation separately.

A valid shape does not guarantee the right label, correct evidence, or complete recall. The semantic gate can filter nominated evidence; it cannot recover every omitted field.

## Done stays disabled

At Chapter 7 and later, every candidate on every page must be accepted or rejected. Resolve them all before exporting.

If you introduced the final guard during Chapter 6 without the review actions, compare your work to the chapter patch. That checkpoint intentionally keeps unresolved candidates advisory until the controls exist.

## Cancellation returns, but the service remains busy

Browser cancellation stops waiting. Native inference may still be running. The service retains its busy slot until that operation settles, even if it already returned a timeout.

Use manual continuation while waiting. Do not start a second service against the same workflow to hide the slot-ownership problem.

## Typecheck fails while a build runs

Run `npm run typecheck` and `npm run build` sequentially. Both mutate Next.js generated state.

A final successful shell command does not prove earlier commands passed. Check each exit status independently.

## A live browser test is skipped

Chapter 10 requires `REDACT_LIVE_QVAC=1`, the desktop project, a warmed model cache, a running production app, and the sandboxed service.

A skip verifies none of the live workflow. Read the test's opt-in condition and rerun only after its prerequisites are ready.

## A dev server exhausts file watchers

For the final browser receipt, stop development mode and use a production build with `npm start -- -p 3102`. Check that the route serves before running the browser test.

## The offline command fails on another operating system

The supplied command uses macOS `sandbox-exec`. Do not treat it as a portable OS enforcement mechanism. A JavaScript fetch replacement alone is also insufficient to constrain every native network operation.

Keep the earlier local-inference exercises separate from claims of process-enforced network denial.

## A passing evaluation still misses a field

Read false negatives, not just `passed`. The pinned threshold is 0.70, so the course gate can pass while missing an expected region.

Keep human review and manual marking. Open the export and check every intended target, including mask edges and all pages. One black-pixel assertion cannot certify an entire document.
