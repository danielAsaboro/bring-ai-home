## Weekly gates

### Week 1 — prove the primitive

- One narrow input produces one inspectable output.
- Model, runtime, hardware, and version are recorded.
- One expected failure is reproduced and classified.

### Week 2 — make ownership structural

- Explicit local assets work without registry fallback.
- Private state has inspection and deletion paths.
- Any peer or cloud route is visible and revocable.

### Week 3 — put it in a hand

- The full user turn works through the real interface.
- Loading, progress, cancellation, approval, and failure are legible.
- At least one other person attempts the task without coaching.

### Week 4 — publish the evidence

- Clean checkout and pinned install succeed.
- Acceptance and negative tests pass on named hardware.
- Known limitations are written beside successful claims.
- The repository tag and demonstration use the same commit.
